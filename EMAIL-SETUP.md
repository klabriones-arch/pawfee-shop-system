# Pawfee Shop email setup (Brevo SMTP)

1. Install Composer from https://getcomposer.org/download/ (select XAMPP's `C:\xampp\php\php.exe` if prompted). In a new VS Code terminal opened at the Pawfee project root, run `composer install`.
2. Create a Brevo account at https://www.brevo.com/. Enable transactional sending if required. In Settings > Senders, Domains & Dedicated IPs, add and verify your sender. Authenticate your own domain if available; free-email senders may be rewritten by Brevo or have delivery limitations. In Settings > SMTP & API > SMTP, copy the SMTP login and generate a standard SMTP key (not an API key).
3. Copy `includes/mail.local.example.php` to `includes/mail.local.php`. Set `username` to the Brevo SMTP login, `password` to the SMTP key, `from_email` to your verified sender address, `from_name` to Pawfee Shop, and `app_url` to the actual full site URL without a trailing slash. Never commit or share the private file. It is ignored by Git and protected by includes/.htaccess on XAMPP. The configured relay is smtp-relay.brevo.com, port 587 with STARTTLS. Do not disable certificate validation.
4. Keep `MAIL_DRIVER` set to `smtp` and `APP_DEBUG` set to false in config.php. Set BASE_URL to the URL path of your actual installation, e.g. `/pawfee` or `/WebSys%20Project/pawfee`.
5. In the project terminal run `php test-mail.php your-recipient@gmail.com` (or use `C:\xampp\php\php.exe test-mail.php your-recipient@gmail.com` if PHP is not on PATH). Check inbox and spam. SMTP errors go to PHP's error log, typically `C:\xampp\apache\logs\error.log` or the configured PHP error log for web requests.
6. Test registration, resend, password recovery, order placement, and contact form. Use real recipient addresses; demo .test addresses do not receive mail. The reset link uses app_url: localhost links only work on the device hosting the website, unless the URL is changed to a reachable deployment address.

No schema changes or database reset are needed. Existing records are retained. SMTP delivery is synchronous; errors do not undo completed orders. Failed messages are not automatically retried. Notifications are recorded regardless of SMTP success; authentication secrets are omitted from new notification records when APP_DEBUG is false. Old mock notification records may contain sensitive data; protect database access. The mail preview is disabled by default. Never enable it on a shared deployment.

The ZIP includes the integration and Composer manifest but not the third-party dependency or credentials. PHP syntax and missing-dependency error handling were checked; live delivery requires configuration and testing on your machine.

Check Brevo Transactional > Logs for delivery results. For authentication errors verify the SMTP login/key and any authorized IP settings. For connection failures check outbound port 587 and TLS configuration. Official guide: https://help.brevo.com/hc/en-us/articles/7924908994450-Send-transactional-emails-using-Brevo-SMTP
